# 04 · 数据模型

> 决策依据：D13（全部换代 qcm_ 前缀新表、DDL 归 qcm 模块、参考 adm）、D5（多零点每台一条记录）、D10/D11。
> 前提：qcm 无生产数据（用户确认），直接换表，不写数据迁移、不做旧值映射。

## 1. 总则

- **FR-04-01** 三张新表，全部 `qcm_` 前缀，DDL 收敛到 qcm 模块 `src/main/resources/sql/qcm_data.sql`（对齐 adm `asm_data.sql` 模式：建表 + seed，幂等可重跑，手动 apply）；权限菜单 seed 另置 `qcm_auth.sql`（见 05）。
- **FR-04-02** 旧表处置：`env_quality_control_plan`（空壳）、`env_quality_control_records`、`env_quality_control_report` 三表 DDL 从 ruoyi `public.sql` / `public_no_shard.sql` / `public_migrate.sql` 种子中删除（详见 06）；已部署库人工 DROP（种子文件头附操作 SQL 注释）。
- **FR-04-03** 时间列一律 `timestamptz`（用户定案 D14）：内部统一时间类型，对齐 adm 先例（`support/TimestamptzInstantTypeHandler` per-mapper 注册，实体用 Instant）；换新表无历史数据，天然一次统一，重绑的现有功能（records/report 页面、报告生成）时间字段一并迁到 timestamptz 语义，模块内不允许 timestamp 与 timestamptz 两套并存。
- **FR-04-04** 主键 `int8`（bigserial）；审计四列 `created_by / updated_by / create_time / update_time` 沿用 ruoyi 惯例。

## 2. qcm_plan（质控任务计划表）

- **FR-04-05** 结构（旧 `env_quality_control_plan` 的名称/类型/浓度概念保留，调度模型换代，`public_no_shard.sql:807-841` 为参考基线）：

| 列 | 类型 | 约束 | 语义 |
|---|---|---|---|
| id | int8 | PK identity | 计划 ID |
| plan_name | varchar(100) | NOT NULL | 计划名称 |
| qc_type | varchar(50) | NOT NULL | 质控类型 code（8 种，含新多仪器零点 ⚠️ OPEN-03） |
| instruments | jsonb | NOT NULL | 仪器代码数组（SO2/NO2/CO/O3）；单仪器类型长度恒 1 |
| schedule_type | varchar(20) | NOT NULL | DAILY / WEEKLY / MONTHLY / ONCE |
| schedule_config | jsonb | NOT NULL | `{hour, minute, weekdays[], monthDays[], onceMode: IMMEDIATE\|SCHEDULED, onceAt}`；按 type 取相关字段 |
| concentration_ppb | numeric | NULL | 需要绝对浓度的类型（跨度/人工核查）；线性/准确度存百分比序列于 duration 侧 |
| flow_rate_lpm | numeric | NULL | 标气流量；零点类 NULL |
| duration_overrides | jsonb | NULL | 用户覆盖的时长参数（稀疏，仅存改过项，键见 01 §6） |
| point_percents | jsonb | NULL | 线性/准确度的量程百分比序列（0~1 小数，如 [0,0.1,0.2,0.4,0.6,0.8]；界面以百分比呈现） |
| plan_start_time | timestamptz | NULL | 计划有效期起（沿用原表 plan_start_time，D18 尊重原表不减列）；NULL=立即生效 |
| plan_end_time | timestamptz | NULL | 计划有效期止（沿用原表 plan_end_time，D18）；NULL=长期有效；窗口外调度不触发（见 01 §FR-01-42） |
| status | varchar(20) | NOT NULL | ACTIVE / PAUSED / FINISHED |
| next_fire_time | timestamp | NULL | 下次触发时刻（调度器维护；PAUSED 置 NULL） |
| last_fire_time | timestamp | NULL | 上次触发时刻 |
| created_by / updated_by | varchar(50) | NOT NULL | ruoyi 用户名 |
| create_time / update_time | timestamp | NOT NULL DEFAULT now | 审计 |

- **FR-04-06** 索引：`(status, next_fire_time)`（调度器扫描）；计划表行数几十量级，不做多余索引。
- **FR-04-07** 不存 cron / 表达式（FR-01-35 同义，存储层落实）。

## 3. qcm_record（执行记录表）

- **FR-04-08** 以旧 `env_quality_control_records` 16 列（`public_migrate.sql:163`）为基线全量迁移，语义不变列 + 新增列：

| 组 | 列 | 说明 |
|---|---|---|
| 保留（语义不变） | id, task_type, quality_control_type, parameter, start_time, end_time, standard_value, monitoring_data, calculated_value, execution_status, execution_log, result_evaluation, created_by, updated_by, create_time, update_time | 列名与语义沿用；execution_status 仍 int4（现有 ExecutionStatusEnum 编码）；phaseTimelines 仍存于 execution_log 文本（现状机制） |
| 改名 | plan_id（原 quality_control_plan_id） | 关联 qcm_plan；历史断链值不存在（新表） |
| 新增 | batch_id varchar(36) NOT NULL | 批次标识（UUID）；一次触发 1..N 条同值 |
| 新增 | trigger_user varchar(50) NOT NULL | MANUAL=用户名 / SCHEDULED=system / REMOTE=sourceName |
| 新增 | failure_reason varchar(50) NULL | 结构化失败原因枚举（FR-02-23）；普通失败仍走 execution_log |
| 新增 | record_snapshot jsonb NULL | 触发时的计划配置快照（名称/类型/仪器/参数摘要）；计划删除后记录仍可溯源 |

- **FR-04-09** 计划快照落在**记录侧**：触发时写 `qcm_record.record_snapshot`（名称/类型/仪器/参数摘要）；计划被删后快照随记录保留（支撑 FR-01-18 删除不级联、FR-02-22 溯源）。
- **FR-04-10** 索引（生产量级毫秒级预算）：`(create_time DESC)`（列表默认序）、`(batch_id)`（批次展开）、`(plan_id)`、`(task_type, execution_status)`（筛选）；建表时一并创建，列表查询不得全表扫。
- **FR-04-11** 多仪器零点一次执行 N 行：各行 parameter=各自仪器、batch_id 同值、start_time 同值；阶段时间线与结果评定各行独立（D5）。

## 4. qcm_report（报告表）

- **FR-04-12** 以旧 `env_quality_control_report` 20 列（`public_no_shard.sql:899-940`）为基线全量迁移，**列与语义不变**（report_name / report_type / report_date / instrument_name / instrument_no / gas_type / filer / reviewer / maintenance_company / report_content / report_note / is_discarded / gas_source / gas_no + 审计四列）；id 改 int8。
- **FR-04-13** 报告生成链路（GenReportTask / 七类报告页 / 导出）全部重绑 qcm_report，行为不变；新零点类型的报告适配不在本期（02 §FR-02-15）。
- **FR-04-14** is_discarded（废弃标记）语义保留；报告删除仍为现有逻辑。

## 5. 状态机

- **FR-04-15** 计划状态机（01 §3 已述，此处数据层约束）：

```
(创建) → ACTIVE ──暂停──→ PAUSED ──恢复──→ ACTIVE
ACTIVE ──ONCE 触发结束──→ FINISHED（终态，仅可删除/查看）
PAUSED/FINISHED ──删除──→ (物理删除)
```

- **FR-04-16** 记录状态沿用现有 ExecutionStatusEnum（含 STOPING 等）+ failure_reason 组合表达冲突失败；不新增记录状态值（冲突记录=失败态+原因列）。
- **FR-04-17** 断电恢复语义保留：onStart 将「运行中」记录改失败（现状 `EnvQualityControlManagerIntegration.java:46-52`），批次内全部记录一致处理。

## 6. 重绑范围（D13 的工程含义）

- **FR-04-18** 现有功能全量重绑新表且行为不变：执行记录页（列表/详情/报告预览/阶段视图/导出/新增/编辑/停止/删除）、报告页与七类报告模板、人工核查页与立即执行、GenReportTask、相关 mapper / domain / XML（Records/Report 两套）。
- **FR-04-19** 重绑属机械替换（表名/列名映射），不夹带行为改动；行为变更只来自本需求集新增能力（触发溯源列 / 批次 / 冲突记录）。
- **FR-04-20** EnvQualityControlCustomMapper 无 XML 的现状（接口存在、实为空置）随重绑一并清理或补齐——以编译与单测结果为准，不留死代码。

## 7. 性能预算

- **FR-04-21** 新表查询路径全部走 §2/§3 索引；计划表操作 O(行数)；记录列表按时间窗 + 索引；无新增 N+1 / 内存分片路径。任何 >1s 查询必须根因分析（生产量级毫秒级铁律）。
