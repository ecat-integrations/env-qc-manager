# 00 · 总体

## 1. 背景

env-quality-control-manager（下称 qcm）当前承担质控执行记录、报告、人工核查、钢瓶气设置，但「质控任务的定义与定时调度」留在 ruoyi 侧，存在以下问题：

- 任务定义在 ruoyi `sys_job` 表（Quartz）：任务组字典「质控任务」（`ruoyi/sql/public.sql:2199`）下种子 21 条（`public.sql:2404-2429`），cron 全部 `0 0 0 * * ?` 且全部暂停态；
- 调度经 ruoyi-quartz bean `QualityControlTask.run(...)`（`ruoyi/ruoyi-quartz/src/main/java/com/ruoyi/quartz/task/QualityControlTask.java:39-72`）反射调 qcm 的 `EnvQualityControlTask`，创建入口是 ruoyi 通用任务页 `#/taskjob/job` 的 cron 表达式表单，对质控场景不友好、与 qcm 业务页面割裂；
- 无对外触发通道：外部集成无法触发质控任务、无法获取执行结果；
- 现有数据表为旧设计：`env_quality_control_plan` 是从未被代码读写的空壳 DDL（`ruoyi/sql/public_no_shard.sql:807-841`），records 表的 `quality_control_plan_id` 引用落空；
- 执行记录缺少触发溯源（谁触发的、本地还是远程）。

## 2. 重构目标

- **G1 计划配置内聚**：质控任务的创建 / 编辑 / 启用 / 暂停 / 恢复 / 删除全部收进 qcm 模块页面，界面用人性化选择（每天几点、每周周几几点、每月几号几点、一次性）替代 cron 表达式。
- **G2 生命周期完备**：启用、暂停、恢复、删除、立即执行；终止正在执行的任务（现有能力，保留并扩展批次语义）。
- **G3 对外 SDK**：进程内 Java SDK 供本系统或其他集成触发任务、查询结果；区分本地 / 远程触发并以「远程标记」留痕。
- **G4 执行留痕完整**：每次触发（含被冲突拒绝的）都有执行记录可追溯：触发源、触发者、失败原因。
- **G5 数据层换代**：全部业务表换 qcm_ 前缀新表（D13），DDL 归 qcm 模块，旧 env_quality_control_* 废弃。

## 3. 范围

### 3.1 IN

1. 新增「质控任务计划」页面（列表 + 分步创建 / 编辑表单）与配套 REST（详见 01、05）。
2. qcm 自建调度引擎：精确唤醒 + next_fire_time 持久化 + misfire 跳过（详见 01）。
3. 计划生命周期：启用 / 暂停 / 恢复 / 删除 / 立即执行（详见 01、02）。
4. 新任务类型「多仪器零点质控」的参数与任务模型：qcm 侧先建好，composer 新 flow 后续接线（详见 02）。
5. 对外 Java SDK：触发 / 查询，异步语义，allowQueue 预留（详见 03）。
6. 数据层换代：qcm_plan / qcm_record / qcm_report 三新表 + 现有功能重绑（详见 04）。
7. 权限与菜单 seed（详见 05）。
8. 旧 sys_job 种子处置 + 等价 plan seed + 旧表 DDL 处置（详见 06）。

### 3.2 OUT

1. composer「多仪器零点」flow 的实现与接线（本期只定义契约，独立任务）。
2. 报告生成器对新零点类型的适配（D4 注明后续调整，独立任务）。
3. SDK 的 HTTP 门面（跨进程调用方，后续按需；接口即契约，不重复设计）。
4. 排队执行（allowQueue 仅预留参数，本期不支持，传 true 明确拒绝）。
5. 旧 sys_job / 旧表**数据**迁移代码（无生产数据，出种子即可）。
6. 质控报告定时生成 job（sys_job id 15，DEFAULT 组）——不属于「质控任务」组，不动。
7. 钢瓶气设置（GasSetting，非 DB 存储）与巡检相关页面（PatrolRunSettings 等）——不涉及本次表换代与调度。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 计划 plan | 一条可调度的质控任务定义（类型 + 仪器 + 调度方式 + 执行参数），存 `qcm_plan` |
| 执行记录 record | 一次质控执行中单台仪器维度的记录（`qcm_record` 一行）；多仪器零点一次执行产生多条 |
| 批次 batch | 一次触发产生的 1..N 条记录的分组，用 batch_id 关联 |
| 触发源 trigger source | SCHEDULED（计划到点）/ MANUAL（页面立即执行）/ REMOTE（SDK 调用），复用 TaskTypeEnum（AUTO=0 / MANUAL=1 / REMOTE=3，LIVE=2 保留不动，`util/TaskTypeEnum.java:11-14`） |
| 触发者 trigger user | MANUAL=ruoyi 登录用户名；SCHEDULED=`system`；REMOTE=调用方标识（远程标记名称） |
| composer | env-calibration-composer，质控执行引擎（7 种 ExecutorType，单飞互斥） |
| 仪器 | 监测分析仪：SO2 / NOx / CO / O3（composer 气体键 NO↔NOx，映射见 `logic/LogicDeviceBindingIds.java:63`） |
| 阶段时长 | 一次执行内各阶段（准备/建立/检查/校准/恢复…）的预估秒数，由参数代入公式计算，非独立常量 |
