## 已定决策（2026-08-20 与用户确认）

| # | 决策 |
|---|---|
| D1 | 调度引擎：qcm 自建（精确唤醒，非每秒 beat），plan 表 + next_fire_time 持久化；misfire（停机错过）=跳过不补跑 |
| D2 | 旧 sys_job 21-41 停用不迁移；重点产出等价 plan seed |
| D3 | 「开始」=启用调度；「立即执行」是独立按钮，走手动链路并记录触发用户 |
| D4 | 多仪器零点=新任务类型（多台**同时**启动零点检查）；旧单仪器零点类型保留，新旧共存，新需求用新的；composer 新 flow 后续接线，qcm 先定义参数与任务模型 |
| D5 | 多仪器零点一次执行 = 每台仪器一条执行记录 |
| D6 | 可计划类型 = 现有 7 种全部（含人工核查）+ 新多仪器零点 = 8 种 |
| D7 | 阶段时长 = 编辑底层参数（预填 composer 默认值）+ 各阶段预估时长只读展示；不改 composer 公式 |
| D8 | SDK = 进程内 Java SDK（api 包零依赖，registry 获取，对齐 adm AirStationSdk 模式） |
| D9 | 校准仪单台自动取用（composer 现状），UI 只展示不选择 |
| D10 | 冲突留痕：计划 / SDK / 手动三类触发被拒**都写执行记录** |
| D11 | 一次性任务执行结束（成功/失败/终止/冲突拒绝）置 FINISHED |
| D12 | 需求文档按域分块 7 件 + 本索引 |
| D13 | 数据表全部换代 qcm_ 前缀（qcm_plan / qcm_record / qcm_report），旧 env_quality_control_* 三表废弃删除；现有 records/report 页面、报告生成、导出、人工核查全量重绑新表；DDL 归 qcm 模块 `src/main/resources/sql/`（参考 adm asm_data.sql / asm_auth.sql 模式） |
| D14 | 新表时间列一律 timestamptz，内部统一时间类型（Instant + TypeHandler，对齐 adm 先例）；重绑的现有功能时间字段一并统一 |
| D15 | SDK 数据供给达到「外部仅凭 SDK 即可生成报告」：触发信息/计划快照/阶段时间线/过程数据/监测/标准/计算/评定全量暴露；报告文档模板渲染不进 SDK |
| D16 | 本次为重构级任务：对照需求审计 qcm 现有代码，异味/漏洞一并优化，重构后性能/质量/规范须达优秀级 |
| D17 | 前端组件与样式技术栈一致性：新页面一律 element-plus（宿主全局注册免 import）+ qcm 现有 `qc:` tailwind 体系 + ruoyi admin 交互习惯，不引入新 UI 库；时间选择等一律 el-time-picker / el-date-picker |
| D19 | 变更批（2026-08-21 用户 review）：流量全类型可设（含零点，默认 4.0）；浓度展示细化（零点只读 0、多点/准确度每阶段浓度点表、单位后端统一 CO=ppm）；时长步重置按钮；修复 zero/span 分支丢 durationOverrides（G-BUG-16）与每月勾选渲染（G-BUG-15） |
| D18 | **表结构设计尊重原表设计，不无故减少字段**（原表与功能经长期确认验证）。qcm_ 新表对旧表列全量保留（含 plan_start_time/plan_end_time 有效期），换代仅限：类型升级（timestamp→timestamptz/int4 id→int8）、语义化改名（plan_id 等）、新增列；任何减列必须单独向用户说明并确认。FR-01-42/43 + 04 §2 已同步 |
